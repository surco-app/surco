# Repaso tras la 1.34.1: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Arreglar los hallazgos del repaso del 12/11 (rendimiento, accesibilidad, diseño y React en la app de escritorio y en la web) sin cambiar lo que la app hace y sin regresiones.

**Architecture:** Ocho tareas por zona de código, una detrás de otra en una sola rama. Cada hallazgo se cierra con su test (rojo antes del cambio) o, si es visual o de rendimiento, con su medida antes y después. Los informes con la evidencia, el `fichero:línea` y el arreglo propuesto están en `docs/superpowers/reviews/2026-11-12-repaso/`. Esos informes son la especificación de cada hallazgo.

**Tech Stack:** Electron + React 19 + TS + Tailwind v4 (`apps/desktop`), vite-react-ssg en Vercel (`apps/web`), Vitest, Biome.

**Spec:** los seis informes de `docs/superpowers/reviews/2026-11-12-repaso/` (desktop-perf, desktop-a11y, desktop-design, react-practices, web-design-a11y, web-perf) y el resumen publicado (ids A1-A21, W1-W9).

## Global Constraints

- Worktree `../surco-wt/repaso`, rama `repaso`, desde `main` local. Merge a `main` local al final, sin push.
- Ningún cambio de comportamiento que el DJ note salvo el que el hallazgo pide. Si un arreglo exige decidir producto, se para y se lleva al usuario (A10 y A14 quedan fuera por eso).
- Cero comentarios de código. `data-testid` para selectores. Copia en seis idiomas, sin guion largo ni dos puntos explicativos.
- Antes de cada commit, desde `apps/desktop`: `npx tsc --build` limpio, `npm run lint` sin errores, `npx vitest run` completo en primer plano. En la web: `npm test -w apps/web` y `npm run build -w apps/web`. Nunca `biome check --write` ni esperar con `pgrep -f vitest`.
- Commits con título descriptivo, sin cuerpo ni prefijo. Un hallazgo (o un par muy unido) por commit.
- Medidas de rendimiento con los scripts de `review/dp/` del scratchpad (bench, open4, prof3) contra la misma biblioteca sintética de 8.000 pistas, con `--user-data-dir` propio.
